# OCT_CT 蓝牙控制 + 高速扫描架构改造方案

## 一、方案背景与已共识决策

基于此前讨论（含 grilling 逐项确认），本次方案的决策已经锁定如下：

| 决策项 | 结论 |
|--------|------|
| 蓝牙模块 | HC-05，一次性 AT 配好波特率后走**透明 SPP 串口桥**，MCU 侧自定义二进制帧协议 |
| 接入串口 | USART1（PA9/PA10），115200，与现有 [usart.c](file:///d:/Embedded/OCT_CT/Core/Src/usart.c) 配置一致 |
| 改动范围 | **完整重构 + 高速化**：扫描热路径脱离任务循环，改为 TIM + DMA + SPI 硬件驱动 |
| 性能目标 | 点表 ≤ **4096 点/帧**，编码后 6B/点 ≈ 24KB；点间隔 ≥ **5us**（约 200k 点/秒，CPU 占用约 15~25%） |
| SYNC 方案 | **ISR 翻转 SYNC**（点同步定时器 + DMA 传输完成中断翻转），正确可靠；2~4us 极端速率的纯硬件 SYNC 作为后续预留路径 |
| 命令集 | 切换形状、调扫描幅度、启停/暂停恢复、调点间隔/速度，并定义可扩展帧格式 |

## 二、现状分析（基于代码核对）

1. 真正的扫描循环写在 [main.c](file:///d:/Embedded/OCT_CT/Core/Src/main.c#L332-L368) 的 `osKernelStart()` 之后 `while(1)` 里。CMSIS-RTOS 下 `osKernelStart()` 不返回，这段逻辑实际**不会正常执行**，扫描点输出实际未真正跑起来。
2. [freertos.c](file:///d:/Embedded/OCT_CT/Core/Src/freertos.c) 只有一个空的 `defaultTask`（`osDelay(1)`），无队列/信号量/互斥锁。
3. SPI3 已配置 8 位、主模式、预分频 /2 → SCLK≈18.75MHz [spi.c](file:///d:/Embedded/OCT_CT/Core/Src/spi.c#L40-L51)；当前用阻塞 `HAL_SPI_Transmit`，无 DMA。
4. 硬件资源：仅 TIM7 作为 HAL 节拍占用，**TIM6 空闲**；**未启用任何 DMA**；SYN 引脚已在 `gpio.h` 定义。
5. 形状生成 `Shape_Generate`（含 float）和 DAC 写逻辑都在 main.c，属于可复用部分。
6. **DAC8563 硬件约束**：每 24 位帧（命令+地址+16 数据）在 SYNC 上升沿锁存；一个点 = X 帧 + Y 帧两个 24 位帧，**必须分别各打一个 SYNC 脉冲**，不能一整串连续 DMA 且 SYNC 一直拉低。

## 三、目标架构（三层解耦）

```
┌─────────────┐   命令队列    ┌─────────────────┐   双缓冲/临界区   ┌────────────────────────────┐
│  BT_Task    │ ──────────▶  │  ScanCtrl_Task  │ ──────────────▶ │  硬件热路径：扫描点输出      │
│ (USART1)    │   cmd_queue   │ (改表/重建/启停) │   只读提交的缓冲区  │  TIM6 + SPI3_TX DMA + ISR   │
│ 解析/分发     │              │                  │                 │  流式打点,定时/数据全脱CPU   │
└─────────────┘              └─────────────────┘                 └────────────────────────────┘
```

- **BT_Task**（替代原 defaultTask，Normal 优先级）：阻塞/中断接收 USART1 字节 → 组帧 → 解析 → 将命令投递到 `cmd_queue`。
- **ScanCtrl_Task**（Normal）：消费 `cmd_queue`，在“安全点”应用变更——停 TIM/DMA → 重建形状点表并重新编码帧缓冲 → 原子切换缓冲指针 → 重新启动。亦承接 KEY1/2/3 按键走同一命令路径。
- **硬件热路径**：TIM6 定住点间隔，SPI3_TX DMA 把帧缓冲流式送出，SYNC 由 ISR 按 24 位帧翻转。CPU 不参与逐点时序，只处理“上传新图案/响应命令”等低速、阻塞的事。

## 四、具体改动（逐文件）

### 1. 新增 `Core/Inc/scan.h` + `Core/Src/scan.c`（核心扫描模块，自包含）

职责：持有形状点表与编码帧缓冲、TIM6 点步进、SPI3+DMA 输出、SYNC ISR、缓冲区双缓冲与启停/配置接口。

- 数据：`uint16_t shape_x[MAX_PTS], shape_y[MAX_PTS]`（MAX_PTS=4096）；编码帧缓冲 `uint8_t frame_buf[MAX_PTS*6]` 与备份缓冲 `frame_buf_bk[]`（双缓冲）。
- 编码：每点 6 字节 `{0x18, X_hi, X_lo, 0x19, Y_hi, Y_lo}`，由 `Shape_Generate`（从 main.c 移入）生成点表后编码写入，幅度按 `amp_pct(0-100)`，见 [main.c](file:///d:/Embedded/OCT_CT/Core/Src/main.c#L160-L219)。
- 硬件：`TIM6` 点间隔（APB1=37.5MHz，预分频与 ARR 配出点间隔 us）；`SPI3_TX` 用 DMA（F407 映射为 **DMA2_Stream1/CH0**，属 RM0090 默认映射，实现时用 CubeMX 的 DMA 配置界面复核确认一次）。
- `Scan_Init()`：将现有 DAC8563 初始化序列（reset/PWR/REF/GAIN/LDAC、SYNC 引脚）从 [main.c](file:///d:/Embedded/OCT_CT/Core/Src/main.c#L306-L314) 迁入；注册 IRQ 优先级（TIM6、DMA TC 设最高抢占级）；不启动。
- `Scan_Start() / Scan_Stop() / Scan_Pause()`。
- `Scan_SetShape() / Scan_SetAmplitude() / Scan_SetInterval()`：停硬件 → `Scan_RebuildTable()` 重建/编码到备份缓冲 → 临界区内切换提交缓冲指针 → 重配 TIM6 → 启动。
- ISR（`TIM6_IRQHandler` + SPI3 TX DMA TC 回调）：
  1. TIM6 更新中断：SYNC 拉低；启动当前点 X 帧（3 字节 DMA 传输）；
  2. X 帧 DMA 传输完成：SYNC 拉高、再拉低；启动 Y 帧（3 字节）；
  3. Y 帧 DMA 传输完成：SYNC 拉高；点序号推进（`(pt+1) % len`）。
  传输期间 SPI 在帧间自然停顿（DMA 未补给即不产生额外 SCLK），正好满足 DAC8563 24 位帧边界。

**为什么做双缓冲**：ISR 只读“已提交”的缓冲与长度；ScanCtrl 改表时先写备份缓冲，再在“停 DMA + 临界区”内切换指针并重启动，杜绝 ISR 读到半构建的撕裂数据。

### 2. 新增 `Core/Inc/bt_protocol.h` + `Core/Src/bt_protocol.c`（可扩展帧协议与命令分发）

- 帧格式（自定义二进制，可扩展）：
  ```
  [SOF 0xAA] [LEN=1+CMD+PAYLOAD] [CMD] [PAYLOAD...] [CRC8]
  ```
- 命令表（`dispatch` 采用函数指针表，便于追加）：
  - `0x01 SWITCH_SHAPE`   payload[0]=形状(0方/1长方/2圆)
  - `0x02 SET_AMPLITUDE`  payload[0]=0..100（幅度%）
  - `0x03 SET_SCAN_STATE` payload[0]=0停止/1启动/2暂停
  - `0x04 SET_INTERVAL`   payload[0..1]=点间隔 us（≥5）
  - `0xF0 ACK`            MCU 回执，payload[0]=错误码
  - 其余 CMD 保留给扩展（未识别回 `0xF0` + 错误码）
- 提供 `BT_OnByte(uint8_t c)`（状态机组帧）、`BT_Parse(帧) → 命令结构`、`BT_Dispatch(命令) → 投递 cmd_queue`。

### 3. 新增 `Core/Inc/bt_uart.h` + `Core/Src/bt_uart.c`（USART1 接收环形缓冲）

- `HAL_UART_Receive_IT` 单字节位到中断，`HAL_UART_RxCpltCallback` 把字节压入环形缓冲并重新启动下一次 IT 接收；ETH 速率为低。
- BT_Task 内 `BT_UART_Poll()`：从环形缓冲取字节 → `BT_OnByte` 组帧 → 完整帧交给 `BT_Dispatch`。
- 保留 USART6 空闲。

### 4. 修改 `Core/Src/freertos.c`（任务与队列）

- 把 `defaultTask` 改造为 `BT_Task`（栈与优先级按需，Normal）。
- 新增 `ScanCtrl_Task`（Normal）。
- 在 `MX_FREERTOS_Init` 创建 `osMessageQueueNew` 命令队列以及两个线程。

### 5. 修改 `Core/Src/main.c`

- 移除 `osKernelStart()` 之后不可达的 `while(1)` 扫描循环（原 [main.c](file:///d:/Embedded/OCT_CT/Core/Src/main.c#L332-L368)），并入 `Scan_Init()`/`Scan_Start()`。
- 移除被迁走的 DAC8563 初始化与 `Shape_Generate`/`DAC_OutAB`/`delay_us` 等，改为调用 `Scan_Init()`。
- KEY1/2/3 改为投递到 `cmd_queue`（与蓝牙同路径），保留作为无蓝牙时的测试入口。
- 保留 `SystemClock_Config`、外设 `MX_*_Init` 不变。

## 五、关键约束与性能边界（写进实现的硬性要求）

- 点间隔 **≥5us** 时 ISR 方案 CPU 占用约 15~25%；追求 2~4us 需走纯硬件 SYNC（本方案仅在文档与接口层面预留，不作为本次交付）。
- ISR（TIM6 + DMA TC）抢占级设最高，**临界区尽量短**，禁止在 ISR 内做浮点/重建/阻塞调用。
- 状态变更一律在 ScanCtrl_Task 内完成，ISR 只读已提交缓冲。

## 六、假设与待确认事项

- DMA 通道映射（SPI3_TX=DMA2_Stream1/CH0）以 CubeMX 复核为准。
